Case study: Cafe website with a database

A cafe site backed by a live Supabase database: a public menu for customers and a dashboard where staff can update it.

The challenge

Building a cafe website is easy. Building one where the menu is managed through a live database is where the real work begins.

Connecting the frontend to a real backend.

The main challenge was integrating Supabase: setting up tables, configuring authentication, and connecting live data to the frontend without breaking the visual experience.

The dashboard needed careful UX so staff could update menu items without any technical knowledge.

Key features

Menu showcase

Food and drink items with images, descriptions and categories.

Management dashboard

A simple admin view to add, edit and remove menu items.

Supabase backend

Database tables, authentication and data synced between the dashboard and the public site.

Responsive layout

Both the public site and the dashboard work on mobile, tablet and desktop.

Process

  1. Brand direction

    I chose a warm look (deep browns, amber tones and editorial type) so the site feels like a brand, not just a menu list.

  2. Database design

    I designed the Supabase schema for menu items, categories and orders, with row-level security and authentication so the dashboard is protected.

  3. Dashboard

    Built with simplicity first. Dashboard actions write to Supabase so changes show up on the public site.

  4. Menu UI and responsive

    The menu leads with photos and category filters. I refined every breakpoint so it feels as good on a phone.
